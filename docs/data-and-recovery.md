# 数据、备份与故障恢复

Coding Hub 的数据保存在本机。默认目录是 macOS 的 `~/Library/Application Support/coding-hub` 或 Windows 的 `%APPDATA%/coding-hub`；实际位置以「设置 → 数据与备份 → 打开数据目录」为准。`CODING_HUB_USER_DATA` 会覆盖此位置。

## 数据目录中的内容

| 内容                                                    | 存放位置                                                         | 应用内备份是否包含                                                 |
| ------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| 项目、工作区、会话、原生 ID、事件、引用、授权记录、设置 | `coding-hub.db` 及运行期间的 WAL / SHM                           | 包含已提交的数据                                                   |
| 输入草稿、未保存编辑缓冲区和视图状态                    | SQLite 的草稿 / 编辑状态表                                       | 包含已持久化的数据；最后尚未送达主进程的输入不能保证进入快照       |
| 检查结果、本轮审阅结果                                  | 已持久化的 SQLite artifact；运行时另有 `tasks/`、`reviews/` 文件 | 包含已写入数据库的结果；执行中的原始基线或临时记录未必已进入数据库 |
| 工具长输出                                              | `outputs/` 独立文本，事件中保存引用和尾部预览                    | 包含快照事件引用的已保存字节，位于备份同名 `.outputs` 附件目录     |
| 应用创建的独立 worktree                                 | `worktrees/`，并关联原仓库 Git 元数据                            | **不包含源码或 Git 仓库内容**                                      |
| 日志、受管进程恢复记录                                  | `diagnostics*.log`、`owned-processes.json`                       | 不包含                                                             |
| 原 CLI 的账号、配置、原生会话历史                       | 由各 CLI 在自己的位置管理                                        | 不包含                                                             |

SQLite 和本地快照没有应用层加密，可能包含项目代码、聊天、图片引用与未保存内容。请使用设备账号权限和适当的磁盘保护措施。数据设置展示的“数据”统计数据库、WAL / SHM 和独立工具输出；“备份”统计数据库快照与配套输出附件。两者都不代表整个数据目录或 worktree 的总占用。

单条工具输出的独立存储有 32 MB 上限；超过上限的内容会明确标记为未保存。聊天先显示最多 64 KiB 尾部预览，支持按需读取完整已保存输出。会话 Markdown / JSON 导出会分批读取事件和输出后生成完整文件；导出失败时保留原目标文件。超过存储上限而从未保存的内容无法通过导出或备份重建。

## 应用内备份

应用启动后检查当日备份，运行期间每小时再次检查；每天保留一份每日快照，最近 7 份每日快照自动轮换。手动、升级前和恢复前快照单独保留，不受这 7 份规则自动清理。

备份位于 `coding-hub.db.backups/`，每份由 `时间-原因-UUID.sqlite` 与同名 `时间-原因-UUID.sqlite.outputs/` 配套组成。SQLite 快照包含已经提交到 WAL 的内容；附件只复制该快照事件声明的输出字节，不混入随后追加的内容。复制或迁移备份时必须把两者放在一起。

恢复前会验证数据库结构、版本、完整性，以及每个输出引用的附件是否可读且达到所需字节数。旧备份没有独立输出引用时可以没有附件目录。列表中可见的损坏备份不代表能够恢复；附件缺失或被截短也会拒绝恢复。

需要手动备份时，在「设置 → 数据与备份」点击「立即备份」。应用关闭期间不会定时创建快照，也没有云端或异地副本。需要设备损坏保护时，应另行保存到可信的备份介质。

## 恢复数据库

1. 处理运行中的 Agent 和检查，保留重要未保存代码，并确认要恢复的时间点。
2. 在设置中选择备份并恢复。界面会说明将结束终端；运行任务或尚在整理的工作区操作会阻止恢复。
3. 应用保留一份恢复前数据库与输出附件快照，替换当前数据库和 `outputs/`，重新加载会话、草稿、编辑状态与设置；替换失败时回滚两者。
4. 核对内容后再继续操作。恢复的编辑缓冲区可能落后于当前磁盘，出现保存冲突时先比较两份内容。

如果当前数据库有效，但当前输出已缺失、被截短或引用非法，无法制作完整恢复前备份时，应用会先将当前数据库、仍可读取的普通输出原字节和缺损清单保存在 `.damaged-restore-UUID/`，成功保留后再恢复选定的有效备份，并显示归档路径。这是排查用原始资料，**不是可恢复的完整备份**，不会列入普通备份列表。归档写入、空间或数据库检查失败时继续拒绝恢复。

恢复数据库**不会回滚磁盘源码、Git index、远程仓库或 worktree 文件**，也不会重新执行历史任务。需要撤销代码修改时使用相应审阅 / Git 流程；不要把数据库恢复当作代码回滚。

启动时数据库无法打开，应用提供已验证备份恢复、打开数据目录及退出入口。损坏原件会保留。新版本数据库不能由只支持旧 schema 的程序安全打开；需要回退时，先保留当前目录，在独立数据目录验证对应旧版本和升级前快照。

## 完整设备或迁移备份

若要保留完整历史与源码，先退出应用，再保存完整数据目录，以及项目原仓库目录；CLI 的原生历史与账号配置需按原工具的方式分别处理。不要在数据库正在写入时，只复制 `coding-hub.db` 而遗漏尚未 checkpoint 的 WAL。

完整目录复制仍不是跨机器 worktree 迁移工具：Git 的 worktree 元数据可能绑定绝对路径。重要代码应先提交、导出 patch 或推送到仓库，再在目标机建立新工作区。不要把只恢复 SQLite、复制几个目录或保留 native ID 等同于已经恢复原 CLI 上下文。

## 常见问题

| 现象                       | 处理方式                                                                                                                                 |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| CLI 没检测到 / 版本过低    | 在终端检查对应 `--version`；在设置中填写完整路径，更新 CLI 后重新检测。                                                                  |
| CLI 可用，但登录或模型失败 | 在原 CLI 中验证账号和模型；新会话选择该账号实际支持的模型。“未验证”不会被视为已登录。                                                    |
| 授权卡片已过期             | 查看回合是否已停止、失败或在 CLI 外部处理；只回复当前有效请求。                                                                          |
| 停止失败 / 工作区仍锁定    | 保留当前文件，重试停止或后台恢复；只有确认受管进程结束后才继续新任务。                                                                   |
| 本地保存失败 / 磁盘已满    | 先保留窗口中的草稿，处理磁盘空间，在恢复入口重试；应用暂停新的执行以防任务有结果却无记录。                                               |
| 文件显示磁盘已改变         | 比较编辑器与磁盘内容，再选重新加载或明确覆盖。覆盖会替换外部修改。                                                                       |
| 撤销被拒绝                 | 文件、权限或路径已在本轮之后改变，或缺少完整文本快照。保留当前版本并手动合并。                                                           |
| 无法清理 worktree          | 先处理运行任务、终端和未保存内容，将相关会话移入回收站；目录中未提交、未跟踪或被忽略的文件也会阻止自动删除。                             |
| pull / push 失败           | 查看上游配置、认证和分叉状态。应用只做快进 pull 和普通 push；冲突需明确处理，不会强制覆盖远端。                                          |
| 完整工具输出不存在         | 核对当前 `outputs/`、备份同名 `.outputs/` 是否完整。恢复一份同时包含数据库与附件的有效备份；从未保存或只保留旧数据库引用的输出无法重建。 |
| 内部包更新入口不可用       | 默认内部构建没有生产更新源，按[安装与升级指南](install-and-upgrade.md)使用维护者提供的下一份构建。                                       |

## 诊断与反馈

在设置中导出诊断会生成版本、平台、存储 / 健康状态和有限日志，不会自动发送。诊断对已知 token、密码和带凭据的 URL 模式脱敏，但不能保证识别所有自定义机密。

提交报告前人工核对诊断、截图和复现项目；不要公开上传完整数据库、数据目录、CLI 凭据或包含真实账号内容的原始日志。反馈入口见[隐私与问题反馈](privacy-and-support.md)。
