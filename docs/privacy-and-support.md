# 隐私与问题反馈

## 本地数据与原 CLI

Coding Hub 保存项目元数据、会话、引用、输入草稿、编辑缓冲区、检查和审阅记录。本地数据库、备份及源码快照可能包含聊天内容、项目路径和代码；这些内容不是匿名数据，也没有应用层加密。具体位置和备份边界见[数据与恢复](data-and-recovery.md)。

Claude Code、Codex CLI 和 OpenCode 的登录、订阅与 API 配置由原工具管理。Coding Hub 不提供托管 token 的账号系统，也不把 CLI 认证文件当作工作区文件自动复制。既有 CLI 项目配置、权限规则和账号状态会影响实际行为。

“本地优先”指客户端与工作数据的存放方式，不代表模型在本地或应用完全离线。提交给 Agent 的消息、文件片段、图片、工具和项目内容是否发送到远程服务，由对应 CLI、模型提供方和配置决定。原 CLI 发起网络请求，并遵循其服务条款。

打开官方文档会调用浏览器；克隆和 Git 同步使用用户的 Git / SSH 配置。配置更新源的正式构建在用户检查或下载更新时联系该更新源。当前代码没有独立的云同步或产品分析上报流程。

## 信任、权限与外部修改

项目未确认可信前，应用限制编辑、Agent、终端、检查和 Git 操作。信任是允许在该项目执行工作的入口，不替代操作系统权限或原 CLI 的授权机制。

授权卡片展示实际请求与范围；CLI 不支持的权限或问答能力不会由界面假造。用户可以拒绝请求、停止回合，并检查原生回复的真实结果。停止失败会保留失败 / 锁定状态，而不会表示工作已经完成。

不同 worktree 可以并行，同一共享目录的受管任务受互斥保护。外部编辑器、手动终端和其他程序仍能修改源码；因此保存、应用工作区和撤销都检查当前文件状态。快照记录的是基线以来的变化，不能证明每项修改都由 Agent 独立产生。

## 通知与诊断

系统通知使用固定的详情提示正文，不把会话标题、提示词、代码、路径或工具输出放进通知正文。可在设置中关闭通知；点击通知会返回应用。

本地诊断日志有大小限制，并对已知凭据模式脱敏。工具输出也有独立的预览与存储上限。脱敏不是项目代码、聊天或图片的通用秘密清理器；用户主动提供的内容仍可能保存在本地会话和快照中。

导出诊断、会话或截图都是明确操作，不会自动创建 Issue、发送邮件或上传数据。任何准备分享的文件都应先由用户核对。真实账号冒烟测试默认不启用；主动运行时可能产生模型费用与原 CLI 的网络请求。

## 报告问题

仓库提供“故障报告”和“能力建议”Issue 表单；它们只提供填写结构，不会自行提交报告。

有助于定位问题的信息包括：

- 应用版本与构建方式：源码、内部包或签名候选。
- 系统与架构：macOS x64 / arm64，或原生 Windows x64。
- 涉及的 CLI 名称、版本与就绪状态，不包含账号 token。
- 最少复现步骤、预期与实际结果，以及是否使用共享目录 / 独立 worktree。
- 经核对的诊断片段或截图；尽量使用不含私密内容的临时复现项目。

账号、证书、私钥、完整数据库、未经核对的原始 CLI 日志和真实项目源码不适合公开 Issue。若问题涉及凭据暴露，应先通过原提供方撤销或轮换相关凭据，再向维护者提供不含秘密的复现说明。

平台结果与发行验收请引用[验证记录](verification.md)。macOS x64 的本机测试、CI 配置、签名候选生成、以及目标机安装成功是不同的证据，不应互相替代。
